# AA v5 변화와 LLM Radar 개편 분석

기준일: 2026-11-17 Asia/Tokyo. 공개 방법론·라이브 데이터와 저장소를 직접 대조했다. 검색 결과의 모델 순위를 그대로 제품 요구사항으로 채택하지 않았다.

## 결론

목표는 한국어로 API 모델 선택을 돕는 의사결정 도구다. 사용자가 업무에 맞는 실측 근거, 비용, 속도, 데이터 공백을 함께 보고 2~3개 후보를 정하게 한다. 단순 순위표 확대는 원본 AA·OpenRouter에 비해 경쟁력이 약하다. 아래 제품 방향은 제안이며 아직 사용자 검증에 의한 시장성 증거는 없다.

## 3. 기존 제품의 문제

1. 데이터가 멈추면 화면이 오래된 날짜를 조용히 보여준다. 열 개수·총 모델 수 검증만으로는 지수·축 전체 결측을 감지할 수 없다.
2. 8축은 우리 자체 집계다. v5 공식 4개 영역과 다르지만 화면에서 차이가 충분히 드러나지 않는다.
3. 구형·현역 모델을 함께 min-max/z-score 모집단으로 쓴다. 상대 점수 50은 절대 정확도가 아니며 모델 추가만으로 변한다.
4. 현재 kNN 루프는 앞서 채운 추정값을 후속 모델의 거리·기증값으로 재사용할 수 있다. 추정이 연쇄된다. 추천 근거에서 제외하고 추후 실측 전용 donor로 별도 수정해야 한다.
5. 지수는 비율척도가 아니다. 지수/달러를 효용이나 '2배 가성비'로 해석할 근거가 없다. 비용·품질 Pareto 후보와 제약 조건이 더 정직하다.
6. 모델별 추론 노력과 공급자 API를 분리해야 한다. 모델 이름 하나에 여러 설정을 평균 내면 비용과 품질의 관계가 깨진다.
7. 미측정 멀티모달을 '미지원'으로 읽히게 해서는 안 된다. 한국어·도구·라이선스도 측정 없음과 지원 안 함을 구별해야 한다.

## 4. 경쟁 환경과 이길 지점

| 서비스 | 이미 잘하는 일 | 우리의 선택 |
|---|---|---|
| Artificial Analysis | 독자 평가, 비용·시간 Pareto, provider 성능, 장기 추세 | 자체 평가기관인 것처럼 경쟁하지 않기; 근거 번역·해석과 선택 흐름에 집중 |
| OpenRouter | 실트래픽, provider별 가격·latency·uptime, 모델 호출 | 실제 라우팅/테스트는 연결; 자체 API 호출 없이 비교 결과 재현성을 제공 |
| Models.dev | provider별 모델 사양·비용·기능 디렉터리 | 사양 수 확장만으로 차별화하지 않기 |
| Arena | 사람 선호 투표와 실제 프롬프트 기반 비교 | 선호와 객관 평가를 한 점수로 혼합하지 않기 |

근거: [OpenRouter 모델 선택 가이드](https://openrouter.ai/blog/tutorials/choose-best-ai-model/), [Models.dev 예시](https://models.dev/providers/inferenceapis/), [Arena 평가 방식 예시](https://news.lmarena.ai/search-arena/).

추천 차별화: 한국어 설명 + 업무별 근거 카드 + 비용 시뮬레이션 + 공유 가능한 선택 결과 + 데이터 건강 상태. '한국어 모델 성능 1위' 주장이나 검증되지 않은 RAG 적합도 점수는 만들지 않는다.

## 5. 성공 조건

기술: 모든 추천에 지수 버전·데이터 날짜·실측 출처·결측 표시, 원본 id 보존, 중요 필드 급감 감지, 다른 버전 사이 순위 변화 미산출.
제품 가설: 첫 방문자가 2분 이내 후보 3개와 이유를 저장할 수 있다. 이는 출시 후 사용성 검증 대상이다.
평가: 대표 과업(문서 자동화/코딩/과학/비용 제한)에서 근거·조건 위반 후보가 없는지 확인. 클릭률·선택 저장률은 향후 동의된 분석 환경이 있을 때 측정한다.
